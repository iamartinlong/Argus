# 证书管理

## 列表

- 状态徽标：签发中 / 有效 / 即将到期（30 天内橙色）/ 已过期 / 已吊销 / 失败
- 到期倒计时显示剩余天数
- 支持导入已有证书（PEM 文本或 PFX/P12 文件，可选绑定部署目标）

## 导入证书

将已有证书（如云厂商签发）导入系统管理：

- **导入方式**：PEM 文本（证书 + 私钥，可含证书链）/ PFX/P12 文件 + 密码（Windows/IIS 常见）
- **文件上传**：可直接选择 .pem/.crt/.key/.pfx 文件，自动读取内容，无需手动复制
- **部署目标**：导入成功后自动部署到所选目标
- **多域名**：PFX 模式自动从证书 SAN 解析域名，无需填写
- **导入的证书**：渠道显示为「导入」，且**不支持续期、吊销、自动续期**（无签发渠道），只能删除或重新导入

## 详情

- SAN 域名、签发 CA、验证方式、有效期、创建时间
- 部署目标徽标与绑定情况
- 任务时间线：签发 / 续期 / 吊销订单记录（含失败原因）
- 部署记录：目标、状态、校验和（SHA256 前 12 位）、消息

## 操作

| 操作 | 说明 | 权限 |
|---|---|---|
| 续期 | 手动触发续期（复用已存私钥与 DNS 配置） | operator+ |
| 吊销 | ACME 证书可对 CA 吊销；云厂商免费证书不支持（本地标记） | operator+ |
| 部署 | 重新部署到绑定目标（或指定目标） | operator+ |
| 下载 | 证书（crt/pem）、私钥（key）、全量 bundle | 私钥需 operator+，记录审计 |
| 删除 | 删除证书与部署记录 | operator+ |

## CSR 模式签发（仅 ACME 渠道）

### CSR 模式 vs 普通模式

普通模式（默认）下，系统自动生成私钥并提交 ACME 签发，私钥由服务端加密保存；
CSR 模式下，**私钥由你自行生成并保留**，只把证书请求（CSR，不含私钥）交给系统，
服务端据此完成签发，全程接触不到你的私钥。

| 维度 | 普通模式（默认） | CSR 模式 |
|---|---|---|
| 私钥由谁生成 | 系统自动生成 | 你自己生成并保留 |
| 私钥存放 | 服务端（加密存储） | 仅在你的机器 |
| 操作方式 | 填域名 → 签发 → 部署 | 生成 CSR → 粘贴 → 签发 |
| 域名来源 | 表单填写 | 从 CSR 自动解析 |
| 自动续期 | 支持 | 不支持（需重新签发） |

### 何时使用 CSR 模式

常规「填域名 → 申请证书 → 直接部署」流程**不需要** CSR 模式，使用默认普通模式即可。
仅在以下场景才考虑 CSR 模式：

- **私钥不能交给服务端/第三方**：高安全要求下，私钥必须保留在自己机器或硬件加密模块（HSM），任何人都不能接触。
- **证书必须配对已有私钥**：某些系统/中间件的证书私钥必须绑定在某台机器上、不能重新生成，可在那台机器上生成 CSR 再交由系统签发。
- **由客户掌控私钥**：客户自己生成并保管私钥，中心端只作为签发代理。

> 对大多数用户而言，CSR 模式用不到，可忽略此功能。
>
> 仅当选择 **ACME** 渠道账户时才显示 CSR 模式开关；云厂商渠道不支持（其 API 不接受外部 CSR）。
> 未选择账户或选择云厂商账户时，该表单项隐藏。

### 使用步骤

1. 在客户端生成密钥对与 CSR（证书请求），域名写入 CN 或 SAN：

   ```bash
   openssl req -new -newkey rsa:2048 -nodes \
     -keyout example.com.key -out example.com.csr \
     -subj "/CN=example.com"
   # 多域名：用 -addext 添加 SAN
   openssl req -new -newkey rsa:2048 -nodes \
     -keyout example.com.key -out example.com.csr \
     -subj "/CN=example.com" \
     -addext "subjectAltName=DNS:example.com,DNS:www.example.com"
   ```

   私钥 `example.com.key` 由你自己保管，**不要上传**；只上传 `example.com.csr`。

2. 证书管理 → 签发证书，选择 **ACME** 渠道账户，打开「CSR 模式」开关。
3. 粘贴 CSR 的 PEM 内容（`-----BEGIN CERTIFICATE REQUEST-----` 起）。
   域名会从 CSR 自动解析，无需再填域名；选择验证方式（HTTP-01 需 80 端口可达，DNS-01 需 DNS 凭据）。
4. 提交签发。签发成功后证书可在界面下载；私钥继续由你保管。

### 注意事项

- 域名取自 CSR 的 CN / SAN，服务端会校验 CSR 签名（证明你持有对应私钥）。
- CSR 模式证书**无法自动续期**（私钥不在服务端）。到期后需重新生成 CSR 再次手动签发，调度器会自动静默跳过这类证书（不产生失败通知）。
- 吊销仍可对 CA 执行。

## DNS 验证账户

ACME DNS-01 场景可选择已创建的 DNS 验证账户（`alidns`/`cloudflare`/`dnspod`/`godaddy`），凭据集中管理、自动复用于续期；亦可在签发表单手动输入（兼容旧流程）。

## 自动续期

调度器每日扫描：到期 < `scheduler.renew_days_before`（默认 30 天）自动续期。
续期优先复用证书绑定的 DNS 验证账户，其次回退签发时快照的 `DNSConfigEnc`。
续期成功后自动重新部署到绑定目标并发送通知；失败会重试并在失败时通知。

## 自动部署时机

签发证书时选择的部署目标，会在**签发成功**后自动部署；**续期成功**后也会自动重新部署。
部署在签发接口返回后异步执行，不阻塞签发流程。

证书的部署目标绑定在**签发后仍可随时增删改**：进入证书详情 →「部署目标」→「编辑」，
勾选/取消目标并保存即可；签发时未选目标，后续也能补充绑定后再手动部署。
详见 [部署目标 · 部署触发时机](/manual/deploy-targets)。

## 到期提醒

通知规则选择事件 `证书到期提醒`，配置提前天数（如 30,14,7,1）——
系统在到期前对应天数发送提醒（每证书每规则每提前天数仅一次）。
